# 可委派的 CNKI 文献检索任务

这是资料协作任务，不是暂停开发的前置条件。请只使用已有合法数据库权限，不付费购买、不绕过访问控制，不向公开仓库上传无权再分发的论文全文或厂家原图。优先提供可复核的书目信息、公式释义、必要的数据摘录和授权范围。

## 可以直接复制给另一个对话的提示词

> 你是 OpenHydroNet 开源暖通水力软件的文献与验证数据研究员。本任务仅做检索和证据整理，不修改软件代码，不把摘要推断写成全文事实，不虚构 DOI、页码、公式或试验数据。软件支持稳态水力，正在补齐设备库、独立验证、可及性和后续热/控制模型。
>
> 请利用已有合法 CNKI 访问，分三组检索下面主题。优先中文核心/权威学位论文、暖通与供热专业期刊中具有完整公式、假设和可重建算例的数据。每组挑选 3–5 篇真正相关的文献，质量优先，不要求凑数量。没有全文权限就明确标注“仅摘要”，不得声称核对过正文。
>
> A（最高优先级）：供热/空调闭式水力网络的独立验证算例。检索词：供热管网 水力计算 环状管网 算例；空调水系统 水力平衡 数学模型；多热源 环状热网 水力工况；分布式变频泵 水力耦合；同程 异程 供回水 管网 水力计算。优先找节点、支路连接、长度、内径、粗糙度、局部阻力、泵曲线、定压点、漏补水、设计/计算流量和压力完整的数据。说明压力是表压/绝压，水头是否含标高，流量单位及水温物性。列出缺失项，不能靠猜测补齐后冒充原文算例。
>
> B：泵阀与水力可及性。检索词：水力可及性 供热 管网；资用压差 最不利用户 水力平衡；平衡阀 阀权度 调节特性；等百分比 Kv 开度 特性；压差控制阀 流量控制阀 饱和；并联水泵 不同特性曲线 变速 工作点；循环水泵 效率 特性曲线 优化。区分定工况检查、约束可行性搜索、局部优化、全局无解证明。给出变量上下界、目标、约束、设备饱和/止回状态和结论性质，不能把一次不收敛称为全局不可行。厂家泵效率只引用有来源数据，不能由流量和扬程反推整机效率。
>
> C：稳态热输送和真实低频热/控制动态（不是水锤）。检索词：供热管网 热力水力耦合 稳态 混合；供热管网 热惯性 传输延迟 动态模型；空调水系统 水泵 阀门 执行器 动态 控制；热网 质量流量 能量守恒 节点混合；换热站 供回水温度 一阶 动态 模型。明确状态量、边界、热容、热损系数、输运延迟、控制器、阀/泵响应、积分方法/步长和适用时间尺度。区分独立稳态扫描、准稳态水力+热/控制状态积分与快速水力瞬态。
>
> 交付：
> 1. evidence.csv：编号、题名、作者、年份、期刊/学位单位、DOI、CNKI 链接、全文/摘要、具体章节/页码/表号/图号、与 A/B/C 的关系、缺失数据、许可/可再分发性。
> 2. models.md：逐个模型重述公式（不要复制整段原文）、符号、SI 单位、假设、适用范围、已知局限及出处定位。特别指出压力水头/测压水头/总水头与标高的差别。
> 3. cases.csv 或 JSON：至少一个“数据完整可重建”的稳态算例；若没有找到就明确报告，不伪造。分别记录“原文直接给出”和“为开源验证独立合成”的数值，不能混淆。
> 4. gaps.md：无法确认的定义、数据缺口、是否存在合法开放全文/作者代码/数据仓库、建议进一步核查的问题。
>
> 不把论文中的真实项目名称、企业机密、未授权图表或全文直接作为开源示例。可给出小规模、独立重建的解析/合成验证模型，但必须说明与论文算例的区别。将资料先放私有交接区 `.local/research/incoming/`（或直接给本对话整理结果），不要让其他代理修改 src/、web/、desktop/ 等核心文件。

## 你需要提供什么

- 现阶段最有价值的是 **A 组一个数据完整的网络算例**，其次是 B 组设备饱和/可及性的严谨定义。
- 如果已有单位允许公开的泵 Q-H-η 数据，可另提供 CSV：流量、扬程、效率、额定转速、介质/温度、允许流量范围、来源与使用许可。没有效率就留空，不能填“典型效率”冒充厂家数据。
- CNKI 原文若不能公开，我们只保留私有核对副本；公开资料采用独立表述、引用定位及有权公开/独立合成的数据。
- C 组是后续模型依据，不需要等待它才继续当前 UI 和工程功能开发。
