# SPEC-001：扫描、敏感性、可及性桌面界面

状态：进行中（2026-10-26） · 覆盖矩阵：H14、X02 · 任务卡：[docs/tickets/](../tickets/README.md)

## 背景
`analysis.py` 已有经过测试的 `scan` / `sensitivity` / `accessibility` API，但没有通过本机服务暴露，桌面用户用不到。本规范把它们变成可取消、有进度、结论表述诚实的桌面工作流。

## 用户故事
1. 运行人员想知道“泵速从 0.6 调到 1.4，各末端流量怎么变”——**扫描**，看表格和曲线，导出 CSV。
2. 设计人员想知道“哪个调节量对最不利末端影响最大”——**敏感性**，看排序后的导数。
3. 调试人员想知道“在泵速、阀位允许范围内，能否让所有末端达到设计流量”——**可及性**，找到可行点后存为工况或应用到工程。

## 范围（本规范做）
- 底部面板新增“分析”页，内含 扫描 / 敏感性 / 可及性 三个子页。
- 后端新增**分析任务**：独立子进程、进度、取消、超时 300 s，与计算任务共用“最多同时 2 个”的限制。
- 分析在**发起时冻结的模型快照**上运行；之后模型被编辑则分析结果标记“过期”，仍可查看，不可应用。
- 扫描：1 或 2 个参数，取值用 起点/终点/点数 生成，单批 ≤1000 点；每点只回传所选**观测量**、状态、问题码，不回传整网结果。
- 敏感性：1 个参数，中心差分，对多个观测量同时给出导数和弹性系数（dY/dX·X/Y）。
- 可及性：约束编辑 + 调节量上下界；无调节量时为固定检查。结论严格使用 GLOSSARY 中的四种表述，“未确定”旁必须显示局部搜索提示。
- 可行点可“保存为工况快照”（不改当前工程）或“应用到当前工程”（进入撤销历史）。

## 默认决策（可由用户推翻）
| # | 问题 | 默认 | 理由 |
|---|---|---|---|
| D1 | 找到可行点后怎么办 | 两个按钮：保存为工况快照 / 应用到当前工程（可撤销） | 不偷偷改工程；比较功能已有 |
| D2 | 默认约束 | 每个末端 `min_flow = design_flow`，可编辑、删除，可增加 `max_flow`/`min_head` | 与现有“需求不满足”诊断一致 |
| D3 | 可调参数范围 | 第一版仅泵速 `speed`、阀开度 `opening`（与可及性一致） | 不改设计参数；管径等以后单独评估 |
| D4 | 分析设置是否存进工程文件 | 第一版不存，schema v1 不变；结果可导出 CSV | 避免为未稳定的格式升级 schema |
| D5 | 观测量 | 默认全部末端流量；可增选任意支路流量/水头差、节点水头/表压 | 覆盖最常见问题 |
| D6 | 二维扫描展示 | 表格 + 按第二参数分组的多条曲线；不做热力图 | 先做可验证的，热力图后补 |
| D7 | 找到可行点后是否继续“尽量少调整” | **是（用户 2026-10-26 决定）**：在保持全部约束满足的前提下，把调节量逐步拉回当前值；局部改进，不保证最小 | 示例中可行点 1.135，实际只需约 1.051 |
| D8 | 调节值精度 | **按设定精度取整（用户决定）**：默认泵速、阀开度均 0.01，可逐项修改；取整后重新验算，不满足时如实提示并保留未取整值 | 现场无法按 16 位小数设定 |

## 不做（本规范之外）
- 全局优化、能耗优化、平衡阀自动整定；时间动态；管径/设计参数扫描；分析设置持久化；热力图。
- 不把“局部搜索未找到”表述为不可行；不估算无数据的电功率。

## 协议
`POST /api/analysis-jobs` `{owner, request}` → `{id,status,progress}`；`GET /api/analysis-jobs/{id}` → 含 `progress:{done,total}`、`result`；`DELETE` 取消。
`request.kind` ∈ `scan | sensitivity | accessibility`，字段见 `analysis.run_request` 文档字符串。子进程入口 `python -m openhydronet.cli analyze -`，进度以 JSON 行写到 stderr。

## 模块边界（便于并行开发）
- 内核：`analysis.py`（请求校验 `run_request` + 精简扫描 + 多观测量敏感性）。
- 服务：`server.py` 中 `Jobs` 泛化为可配置命令/超时/进度。
- 前端：`web/src/analysis.ts`（纯函数：取值生成、请求组装、单位换算、CSV），`web/src/AnalysisPanel.tsx`（外壳）、`web/src/useAnalysisJob.ts`（任务生命周期），`ScanView.tsx`、`SensitivityView.tsx`、`AccessibilityView.tsx` 各自独立。`App.tsx` 只增加挂载与两个回调。

## 完成标准
- 每张任务卡的验收标准均有自动测试；`tests/ui.analysis.cjs` 在真实 Electron 中走通三个子页并已加入 CI。
