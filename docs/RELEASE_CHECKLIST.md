# 双平台免费发布检查单

当前：未公开发布。GitHub 主仓库、Gitee 镜像、视频平台及账号待用户确认。用户已授权免费开源公开发布，但没有授权代选个人/组织归属或改写现有远端历史。

## 本地准备

- [x] 独立代码、公开人工示例、中文 README、Apache-2.0。
- [x] 贡献指南、安全说明、问题模板、路线图、参考功能矩阵和依赖许可清单。
- [x] 可执行测试和真实界面流程。
- [ ] 完成覆盖矩阵 A/B/C 全部承诺；当前只允许发布预览。
- [ ] Windows 原生启动/计算/工程往返/PDF/缩放/退出验收。
- [ ] 正式审核两条视频（不只脚本），确保版本和提交一致。
- [ ] 正式发行前依赖安全漏洞/支持周期复核及必要升级。

## 发布前隐私和版权

- [ ] 最终发布前对当前文件及完整 Git 历史执行隐私审计；本轮静态工具仅覆盖当前跟踪文件/产物，不能冒充历史审计。不得公开原 docx、提取截图、`.local`、访问凭据、私人路径或真实工程。
- [ ] 实际安装包保留 Electron/Chromium、Python、NumPy/SciPy 捆绑许可。
- [ ] 安装包、示例、手册、视频素材均有来源授权；无虚构厂家数据。
- [ ] 版本号、源码提交、构建清单、变更日志和 SHA-256 一致。

## 用户最小确认项

1. GitHub 账号/组织及目标仓库 URL（主仓库）。
2. Gitee 账号/组织及目标仓库 URL（镜像）。
3. 如已有安全认证，使用本机安全认证方式；否则由用户在本机完成登录，不在对话提供密码/令牌。
4. 视频平台、账号和是否允许公开上传当前预览视频。

缺少以上条件时继续本地工作，不请求明文凭据，不创建猜测的仓库，不推送，不写“已发布”。

## 双平台执行（待授权目标后）

- 不覆盖既有仓库、不 force push、不修改已有公共历史。
- GitHub 主仓库和 Gitee 镜像使用同一提交和标签 `v0.1.0-preview.1`，明确开发预览。
- 先在目标平台检查附件大小/类型限制，实际上传 Windows 候选/经验证发行包、示例、手册及 SHA-256。
- 视频按实际平台能力托管；代码平台 README 链接指向有效播放入口，不假定两边可上传全部大视频。
- 实际访问仓库、标签、下载附件、README 文档和图片链接；记录 URL/提交/校验值。

发布验收必须是可访问地址、标签和下载文件，不是仅设置了 remote 或写了 CI 配置。
