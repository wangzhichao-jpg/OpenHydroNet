# T-015：W4-06 首次冷启动超时：启动窗口、放宽时限、分类错误与重试

来源：[preview.4 Windows 验收](../../validation/windows/0.1.0-preview.4/验收记录.md) · blocked_by：—

## 范围
- 启动即显示本地启动窗口（无网络、沙箱、无 Node）：“正在启动计算内核…”，显示已等待秒数；10 s 后提示“比平时慢：首次启动或杀毒软件扫描新文件时可能需要一分钟”。
- 后端就绪时限 120 s（`OHN_BACKEND_TIMEOUT_MS` 可调，仅用于诊断/测试）；60 s 内的冷启动不得失败。
- 失败分类：超时 / 进程退出（退出码与 stderr 末尾）/ 找不到运行时 / 通信协议不匹配；在启动窗口显示中文说明与“重试”“退出”，重试前确认旧进程已停止。
- 等待与分类逻辑放入 `desktop/backend-launcher.cjs`，`main.cjs` 只做编排。

## 验收
- Node 单元（Linux/Windows CI）：用 Node 子进程替身覆盖就绪、慢就绪、超时、提前退出、启动错误、协议不匹配、慢提示回调。
- 真实 Electron（Linux）：`OHN_PYTHON` 指向 20 s 后才就绪的替身 → 不报错、启动窗口显示等待提示、随后主窗口正常；超时场景 → 显示超时说明，点“重试”后恢复。
- Windows 冷启动由 PC 回归（HANDOFF preview.5）。

## 完成记录（2026-10-27）
- `desktop/backend-launcher.cjs`：`waitForBackend`（就绪行可跨数据块、token/协议/端口校验、慢提示回调、超时不杀进程由调用方处理）与 `BackendStartError`（timeout / exit / spawn / protocol）、`startupHint`。
- `main.cjs`：启动窗口（`startup.html` 无脚本 + 沙箱 preload，只有两个 IPC）创建后 0.7 s 未就绪才显示，热启动不闪烁；每秒更新已等待秒数，10 s 后慢提示；时限 120 s（`OHN_BACKEND_TIMEOUT_MS` 仅诊断/测试用）；失败时先停旧进程再显示原因与“重试/退出”；运行期计算进程退出改为中文标题对话框。
- 主窗口在加载前即登记，避免 ready-to-show 先到时启动窗口关闭被误判为用户退出（自查发现）。
- 测试：Node 单元 8 项（Linux/Windows CI）；真实 Electron `tests/ui.startup.cjs`（仅 Linux，Windows 输出 SKIP）：20 s 慢启动成功且无对话框、3 s 超时后重试成功且旧进程已停止、退出码 3 区分显示并可退出。E2E 改用 `mainWindow(app)` 按地址找主窗口；`tools/record_video.cjs` 同步。
- 未在本机验证：Windows 真实冷启动（交 PC 回归）。
